# チェックアウト（決済・送料・商品モデル・多言語）

管理画面の設定項目が存在することの確認と、**チェックアウト画面に実際に反映されるか**の実機確認をまとめる。実機検証にあたっては、[購入ゲート](./cart-validation-function.md)のチェックアウトルール `member tag gate` を一時的に無効化し、終了後に有効へ戻した。

## 決済手段（代引き・銀行振込）→ 可

設定 > 決済 > 手動の決済方法 に、標準の選択肢として以下が用意されている。

- 銀行振込
- 郵便為替
- 代引き (COD)
- カスタム決済方法を作成する

いずれも「手動の決済方法」であり、**入金確認と消込は管理画面での手作業**になる。注文は発送済みにする前に手動で承認する必要がある。運用方針の詳細（代引きと銀行振込の運用負荷の違い）は `docs/human/requirements.md` を参照。

なおコンビニ決済・QRコード決済（LINE Pay、PayPay 等）は「人気の決済方法」として外部の決済サービス経由で提供されている。要件には含まれていないが、必要なら別途検討する。

### 実機確認: チェックアウトに表示される

設定 > 決済 > 手動の決済方法 から2つを作成した。

| 決済方法 | 追加情報（顧客に表示） |
|---|---|
| 代引き (COD) | 商品お届け時に配達員へ現金でお支払いください。 |
| 銀行振込 | ご注文後1週間以内にお振込ください。お振込の際、お名前の前に注文番号をご入力ください。 |

銀行振込の「決済手順」には振込先情報を入れた（検証用ダミー）。この欄は顧客が注文した後に表示される。チェックアウト画面の実測:

```
Payment
  Credit card
  Cash on Delivery (COD)
  Bank Deposit
```

**両方とも選択肢として表示された。** 要件を満たす。

## 送料（重量別・地域別）→ 可

配送オプションの料金タイプに以下が選べる。

| 値 | 表示 |
|---|---|
| `flat_rate` | 一律 |
| `carrier` | アプリまたは配送業者による計算 |
| `order_amount` | 注文金額 |
| `weight` | **パッケージの重量** |

重量別の料金表を組める。既存の「通常配送」にも「¥7700以上で無料」という注文金額条件が設定されており、まとめ買い送料無料も標準機能で実現できる。

地域別については、配送ゾーンで日本の**47都道府県が個別に扱える**ことを API で確認した。北海道・沖縄を別ゾーンに切り出して加算料金を設定できる。配送アプリとしては プラスシッピング（ヤマト・日本郵便・佐川、無料）が引き続き利用可能。

### 実機確認: 重量条件に応じて正しく計算される

バリエーションに5kgを設定し、配送ゾーン「国内配送」に重量条件付きの料金を2つ作成した。

| 料金名 | 条件 | 価格 |
|---|---|---|
| 重量別テスト 〜5kg | 0kg以上5kg以下 | ¥800 |
| 重量別テスト 5kg超 | 5.01kg以上 | ¥1,500 |

数量1（合計5kg）では「重量別テスト 〜5kg ¥800」、数量2（合計10kg）では「重量別テスト 5kg超 ¥1,500」がそれぞれ表示された。**バリエーションの重量が数量分だけ合算され、重量条件に応じて表示される料金が切り替わった。** 5kg / 10kg / 20kgの料金表は組める。配送先の都道府県セレクタにはHokkaidōからOkinawaまで47件が並んでおり、地域別のゾーン分割も問題ない。

### 実機確認: 北海道・沖縄を別ゾーンに分離（2026-10-09、Issue #13）

設定 > 発送と配達 > 配送（一般プロファイル）> 配送エリア で以下を実施した。

1. 既存の「国内配送」ゾーン（日本47都道府県が1ゾーンにまとまっていた）の地域一覧から、北海道・沖縄県のチェックを外した（47県→45県）
2. 新しいゾーン「北海道・沖縄」を作成し、北海道・沖縄県の2県だけを割り当てた
3. そのゾーンに配送オプション「通常配送（北海道・沖縄）【検証用ダミー】」（一律¥1,500、5〜8営業日）を追加した。**金額は検証用のダミー値**で、実際の加算額は事業判断待ち（Issue #2参照）

実機のチェックアウトで配送先都道府県を沖縄県にしたところ、自動的にこのゾーンの配送オプション（¥1,500）が表示され、合計金額に反映されることを確認した。本番移行時は「通常配送（北海道・沖縄）」の金額を実際の加算額に差し替える必要がある。

**ハマりどころ**: 配送オプション追加モーダルの「輸送時間」フィールドはブラウザのネイティブ`<select>`で、クリックしても選択肢がスクリーンショットに映らず、Returnキーでも反応しなかった。英数字・ひらがなの先頭文字（例: 「5」）をキー入力するタイプアヘッド操作で選択できた。この項目は未入力だと保存がブロックされる必須項目。

## 商品モデル（5kg / 10kg / 20kg）→ 可

バリエーションごとに重量を持てる（`inventoryItem.measurement.weight`、単位はキログラム）。重量別送料と組み合わせられる。「商品3つ × 重量3種」はバリエーション軸で表現するのが素直。

実装では「商品3つ（コシヒカリ 5kg/10kg/30kg）、各1バリエーション」という構成になっており、バリエーション軸にはしなかった。どちらでも要件は満たせる。

### 実在する商品の重量が0kgのままだった不具合（2026-10-08発見・修正、Issue #12）

上記の重量別送料検証は「重量別テスト」という検証専用のバリエーションを別途作って行ったもので、実際に販売する3商品（コシヒカリ 5kg/10kg/30kg）の配送設定の重量は、登録時から**ずっと0.0kgのままになっていた**。つまりこれまでは重量別送料が実際には機能しない状態だった。各商品の「配送」セクションで重量を正しい値（5/10/30kg）に修正・保存して解消した。**新しく商品を登録する際は、重量を入れ忘れていないかを必ず確認すること。**

## 多言語（日英越中）→ 可

設定 > 言語 から言語を追加できる。選択肢は137言語あり、対象になりそうな言語はすべて含まれていた。翻訳の入力には Shopify Translate & Adapt（公式・無料）を使う。同時に使える言語数の上限は Basic プランで20言語まで（[plan-dependent-features.md](./plan-dependent-features.md) 参照）で、4言語なら余裕がある。

### 実機確認: チェックアウトまで翻訳される

ベトナム語を追加して公開した（管理画面から。API には `write_locales` スコープが必要だったため UI を使用）。`?locale=vi` でチェックアウトを開いたところ、配送・支払い・注文確定などShopify標準の文言はすべてベトナム語で表示された。**Shopify が用意しているチェックアウトの文言は、翻訳を1つも入力せずにベトナム語で表示された。**

### ただし自分で入力した文字列は翻訳されない

同じベトナム語チェックアウトでも、以下はそのまま残った。

```
重量別テスト 〜5kg        ← 配送料金名（自分で入力）
通常配送 / 速達           ← 同上
Cash on Delivery (COD)   ← 決済方法名
Bank Deposit             ← 同上
```

配送料金名と決済方法名は**マーチャントが入力した文字列**なので、自動翻訳の対象外である。商品名・商品説明も同様。**本番では以下を4言語分用意する必要がある。**

- 商品名・商品説明
- 配送方法の名称
- 決済方法の名称と、追加情報・決済手順の文面（銀行振込の案内文は特に重要）
- ページ文言（特商法表記、返品ポリシー、登録ページの説明）
- 通知メールの文面

Translate & Adapt を使えば管理画面から入力できるが、**文言そのものは人間が用意する**。生成AIで下訳を作る方針であれば、法的効力のある文面（特商法・返品ポリシー・振込案内）だけは母語話者の確認を推奨する。

## 動的チェックアウトボタンの非表示は維持されている

検証の過程で `templates/product.json` の `show_dynamic_checkout` を `false` にしたままにしてある（[cart-validation-function.md](./cart-validation-function.md) 参照）。Buy it now ボタンは表示されない。本番テーマでもこの設定を維持すること。
