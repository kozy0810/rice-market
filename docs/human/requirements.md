# 要件定義

技能実習生向けお米販売サイト。

このドキュメントは人間が読むための要件定義書です。実装時の技術的な検証結果・手順・注意点は `docs/shopify-verification-log.md` にまとめています。

## 当初の要件（2026年9月時点）

- 限られたユーザーしか買えないサイトにする。会員登録が必要。
  - 登録時に、ユーザーは派遣元の組織に紐づく。
  - 派遣元ごとに登録URLが異なる（UUIDのような形を想定）。
  - 卒業後は「未所属」の状態になる。ただし登録時に最初から「未所属」として登録することはできない。
  - 派遣元情報は、管理者がダッシュボードから追加する。
- 商品一覧ページには3つ程度の商品を表示する。詳細ページにも遷移できる。
  - 一覧ページからカートに追加できる。
  - 商品には5kg・10kg・20kgのように重さの違いがある。
- 多言語対応必須。
- 代引き引き換え、銀行振込必須。

### 派遣元組織とユーザーの紐付けについて

組織Aがあるとする。組織Aをトークン「xxx」に紐づけ、会員登録ページを `https://rice-market.com/signup/xxx` のような形にする。組織Bの場合は `https://rice-market.com/signup/yyy` のようなイメージになる。

`https://rice-market.com/signup` という素のURLからは登録できないようにする。

## 確定した事項（2026年9月20日時点）

技術検証と並行して、以下の事業判断が確定しました。

- **卒業のトリガー**: 管理者がダッシュボードから手動で操作する、または本人からの申告を受けて管理者が操作する。具体的な操作手順は「卒業・転籍の運用手順」を参照。
- **転籍**: 想定する。技能実習生が別の派遣元に移ることがあるため、派遣元は登録時に固定されるのではなく、後から変更されうるものとして設計する。具体的な操作手順は「卒業・転籍の運用手順」を参照。
- **対応言語**: 日本語・英語・ベトナム語・中国語の4言語。（Shopify Basicプランで20言語まで同時に扱えることを確認済みのため、4言語であれば余裕がある。）
- **Shopifyプラン**: まずBasicプランで始める。
- **ロイヤリティ**: 派遣元に売上の1%を支払う。スコープ内。
  - 転籍・卒業によって顧客の現在の所属が変わっても、過去の注文の派遣元記録は変わらないようにする（注文時点の所属を注文側に記録する）。
- **決済の運用方針**: 代引きを主軸とし、銀行振込は補助的な位置づけとする。技能実習生はクレジットカードを持っていないことが多いと想定されるため。
  - 銀行振込は、注文を受けてから入金を確認できるまで発送できない。入金明細には振込人名義・金額・日時しか出ず注文番号が載らないため、突き合わせ（消込）の負担が大きい。負担を減らすため、振込時にお客様の氏名の前に注文番号を入力してもらう案内を用意する（例:「1001 グエン」）。
  - 未入金の注文は、注文から1週間を目安に自動キャンセルする。

## 卒業・転籍の運用手順（誰が何を見て操作するか）

タグの命名規則は `docs/specs/dispatch-org-tagging.md` を参照。顧客は `member`（会員フラグ）と `org:<org_code>`（所属派遣元）の2種類のタグを持つ。

### 卒業（未所属になる）

1. 管理者が Shopify 管理画面の「お客様」から対象者を検索する（氏名またはメールアドレス）
2. 顧客詳細ページの「タグ」欄から `member` タグを削除する
3. `org:<org_code>` タグはそのまま残してもよい。削除するかどうかは運用判断だが、`member` タグさえ外せば購入ゲート（Cart Validation Function）が即座に働き、以後の購入はできなくなる
4. 過去の注文には影響しない。注文時点の派遣元は注文側のタグ・メタフィールドにスナップショットとして記録済みのため（`docs/specs/dispatch-org-tagging.md` 参照。Issue #8 実装後）、顧客側のタグを変更しても過去のロイヤリティ集計は変わらない

### 転籍（別の派遣元に移る）

1. 管理者が同様に対象者を検索する
2. 顧客詳細ページの「タグ」欄で、旧派遣元のタグ `org:<旧org_code>` を削除し、新派遣元のタグ `org:<新org_code>` を追加する
3. `member` タグはそのまま維持する（購入資格は継続する）
4. 転籍後に新たに作成される注文には、転籍後の派遣元タグが記録される。転籍前の注文記録は変わらない

### 卒業・転籍の申告経路

本人からの申告（メール等、システム外）を受けて管理者が上記操作を行う想定。システム側に申告フォームは設けない（要件定義の「まだ決まっていないこと」には含まれない、運用でカバーする）。

## 法令上の留意事項

**米トレーサビリティ法（米穀等の取引等に係る情報の記録及び産地情報の伝達に関する法律）が適用されます。** 国内で米・米加工品を販売する事業者はすべて対象になり、小売販売事業者も明示的に含まれます。義務は次の2つです。

1. 取引等の記録の作成・保存
2. 産地情報の伝達（一般消費者への販売時も必要）

このため、商品データには産地情報を必須項目として持たせる必要があります。具体的な対応方法は、農林水産省の窓口や専門家への確認を推奨します（このドキュメントの記載は法的助言ではなく、調査結果です）。

なお食品表示法に基づく精米表示（名称、原料玄米の産地・品種・産年、内容量、精米年月日、販売者）も別途かかります。主に商品パッケージ側の話ですが、通販の商品ページでどこまで表示すべきかは別途確認が必要です。

## まだ決まっていないこと

- 送料の実額（配送業者の選定と、重量別・地域別の料金表）
- 翻訳文の最終確認体制（生成AIで下訳を作る方針だが、特商法表記・返品ポリシー・振込案内などの法的な文面は母語話者による確認を推奨）
- 特定商取引法に基づく表記の具体的な内容（事業者名・住所・連絡先。住所は開示できることは確認済み）
